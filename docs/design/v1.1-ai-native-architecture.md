# v1.1 AI-Native 交易架构设计(评审修订版)

> 状态:v1.1,评审后修订
> 日期:2026-10-09
> 变更:v1.0 → v1.1 吸收评审意见,核心变化:
> ① 线性 Phase 改为 2×2 因子实验,信息增量(B)成为唯一门禁;
> ② Critic 必须独立(不同模型/信息集),新增信心校准测量;
> ③ invalidation 开仓时锁定,time-stop horizon 设硬上限;
> ④ cost_validator 只许算术输入,禁用 AI 信心;
> ⑤ 测量层加入预注册、块 bootstrap、多重检验校正、复现清单;
> ⑥ 明确各层 kill criteria 与总回退线。

## 0. 前提:核心命题是假设,不是结论

v1.1 的出发点:**"给 AI 更多信息、知识、决策权就能产生可测
alpha"目前是没有证据的假设。** 已有的三个实验事实
(双模型等价、零智能等价、多头偏见模型无关)只证明:

> 在纯技术特征 + 5 动作 × 5 币 + 5 道门控的配置下,
> LLM 与规则不可区分。

这与三种互不兼容的解释都相容:(a) 系统压制了 AI;(b) 该任务
在此频率/信息集上没有可提取的 alpha;(c) LLM 不擅长此类任务。
**v1.1 的全部设计目标不是"实现 AI 交易",而是用最小成本、
最严纪律区分这三种解释。** 若答案是 (b) 或 (c),回退到
"规则执行 + AI 研究层"是正式结论,不是失败。

## 1. 实验设计:2×2 因子,并行而非线性

v1.0 的线性 Phase(B→C→D→E 在旧门控下跑,Phase 5 才切沙箱)
有两个已识别的混淆:门控可能抹平增量(假阴性),或提前放开
用亏损换数据。v1.1 改为两个因子同时变化:

```text
因子 I:信息集      I0 = 纯技术特征   I1 = 全情报栈
因子 G:约束方式    G0 = v0.8 门控    G1 = 风险沙箱(门控转 shadow)

        G0(门控)          G1(沙箱)
I0      A 组(= v0.8 现状)  C 组
I1      B 组               D 组
```

- **A 组**就是正在运行的 30d 回放(air + v0.8 门控),零成本基线;
- **B 组是唯一的门禁实验**:I1×G0。信息增量若存在,应在旧
  门控下也能被观察到(门控只过滤提议,不禁止信息改变提议分布);
- **C 组**隔离"放开约束"本身的效果(AI 是否只是想要更多
  自由度,还是真有判断);
- **D 组**是全量配置,只有 B 或 C 显示增量后才有意义。

所有组:同窗口、同执行器、同成本模型、同 null test
(rule-proposer 同步跑)。沙箱组用**缩小版风险参数**
(单笔风险、敞口减半),不用真实亏损换数据。

**kill criteria(预注册,先于实验写下):**
- B 组相对 A 组的 PF 差异,块 bootstrap 95% CI 覆盖 0
  → 信息层无增量,**停止情报栈投入,C/D 不启动**;
- C 组相对 A 组 CI 覆盖 0 → 放开约束无增量,门控保留;
- 两组都无增量 → 回退"规则执行 + AI 研究层",项目转向。

## 2. 信息层:逐源验证,不打包接受

评审正确:公开信息大概率已被定价,且 30min 频率下短时效信号
(订单簿失衡、清算热力、社交 z-score)进 prompt 时可能已失效。
v1.1 的纪律:

**2.1 每个信源先独立做信号有效性检验,再决定进不进 prompt。**
不进 Agent、不经 LLM:直接统计信号与未来 1h/4h/24h 收益/波动
的关系(类似 v0.4 的 Social Signal Replay)。无前瞻相关性的
信源直接淘汰——**先证明是信号,再谈喂给 AI**。

**2.2 结构化摘要的分工**:确定性聚合(均值、z-score、变化率)
由代码做,这层没有"规则筛选世界"的问题,因为是算术不是判断;
跨来源的矛盾解读、叙事综合才交给 LLM。confidence 不由模型
自评(循环论证),由数据层给出可计算指标(样本量、来源分歧度、
staleness)。

**2.3 给 AI 计算工具。** 评审指出 LLM 不擅长数值推理——正确。
决策 prompt 提供只读工具:get_feature(任意窗口重算)、
query_trades、calc(费用/仓位/盈亏算术)。回放中等价实现为
预计算工具结果。**富 prompt 若没有工具,只是让模型在数字里
编故事。**

**2.4 时效性**:所有信号带 timestamp/age/staleness 上限,
超过上限的信号标记 STALE 而非静默丢弃(让 AI 看到"这个
数据过期了"本身是信息)。

## 3. 知识层:先证冗余,再谈注入

评审正确:LLM 预训练已含大量交易知识,playbook 注入可能冗余;
检索注入会诱导强行匹配 setup;自我复盘有后见之明。纪律:

- playbook 库是**实验变量,不是默认组件**:只在 B 组证明
  信息增量后才作为新因子测试,且设负对照(随机注入不相关
  playbook,若效果相同说明是 placebo);
- 复盘记忆的生成**禁止自我归因**:教训的"对错"标签由结果
  数据确定性打分(持有期收益、相对基线超额),LLM 只负责
  把已定性的结果写成可检索文本;
- 记忆条目带**时效衰减**与**市场环境标签**,检索时按
  regime 匹配 + 必须同时召回正例与反例(防止单行强化);
- 记忆对决策的影响单独 A/B(同窗口,有/无记忆注入)。

## 4. 决策层:Critic 必须独立,信心必须校准

v1.0 的三阶段同模型设计,偏见相同,Critic 容易沦为形式反对。
v1.1:

**4.1 Critic 独立性**(三条至少满足两条):
- 不同模型(如 air 决策,glm-5 或 flash 反驳);
- 不同信息集(Critic 只看到 thesis 和反方证据检索结果,
  不看 Trader 的正方论证全文,避免锚定);
- 不同 prompt 立场(系统性空头立场 vs 系统性多头立场,
  两者都要,对冲单方向偏见)。

**4.2 信心校准是第一类测量指标。** 每个决策的信心档位与实际
结果(是否触发 invalidation、净盈亏)持续记录,定期输出
校准曲线。**信心与结果不单调相关 → 仓位分档功能永久关闭**
(随机加杠杆不如固定仓位)。这是硬规则,预先写下。

**4.3 thesis/invalidation 纪律**(采纳评审):
- invalidation 在开仓时刻**写入数据库锁定**,任何修改
  (放宽、移动、延长时间)被拒绝并记录为违规事件;
- horizon 设硬上限(如 24h),AI 不能用拉长 horizon 逃避退出;
- "判断对但太慢"在复盘中计为失败。

## 5. 风险沙箱:参数治理与相关性

沙箱方向不变(AI 无权修改、确定性执行),补充:

**5.1 参数治理**:沙箱参数值不由 AI 提议生效;调整只能在
实验之间、由人工或经 30d A/B 验证的配置变更流程进行。
参数值本身纳入实验元数据(prompt/config/data version)。

**5.2 组合层相关性**:单币种敞口上限防不住多币同向共振
(BTC/ETH/SOL/XRP/SUI 在 risk-off 时相关系数→1)。增加
**方向级总敞口上限**(全组合同向名义敞口合计 ≤ X)与
压力项(所有持仓同向 -10% 时组合损失 ≤ 日亏熔断的 N 倍)。

**5.3 cost_validator 只许算术**:费用、滑点、屏障几何结构
是输入;**AI 的信心/预期收益不是输入**(那是主观判断,不是
算术——评审正确)。

**5.4 熔断的恢复路径**:日亏/连亏熔断后不是简单停摆,而是
进入"只减不开 + 强制复盘报告"模式,下一交易日自动复位
(复位事件入日志)。熔断防的是单日失控,不应阻止策略恢复。

## 6. 测量层:统计纪律(全部采纳)

30d 是**筛查,不是证明**。明确写入:

- **预注册**:每个实验开工前写下假设、主指标、kill criterion,
  存 docs/experiments/;事后报告必须对照预注册,不允许
  "换指标讲故事";
- **统计方法**:主效应用块 bootstrap(块长 ≥ 1 天)给 95% CI;
  多指标/多币种/多 regime 的次要分析做 Holm 校正;
  报告效应量 + CI,不报告裸 p 值;
- **功效自觉**:30d/几十笔交易只能检出大效应;检不出时
  结论写"证据不足",不写"无差异";
- **决策质量评分**:Good/Bad/Unclear/ExecutionFailure 的
  评分细则预先定义,由确定性规则 + 独立模型双评,
  不允许决策模型自评;
- **复现清单**:每个 experiment 记录 model 版本、温度、
  prompt hash、config hash、数据快照 id、采集器版本、
  代码 commit;LLM 非确定性显式承认(同一 prompt 重跑 N 次
  的决策一致率本身作为指标上报);
- CoT 不入库不变;但**结构化的中间产物**(阶段一的判断、
  Critic 的反对意见、信心档位)入库,否则无法归因。

## 7. 最可能失败模式与应对(评审 §7 全部接受)

| 失败模式 | 应对 |
|---|---|
| B 无增量 → 陷入"prompt 不够好"无限调参 | kill criterion 预注册;B 失败即停情报栈 |
| 沙箱参数过拟合历史 | 参数只在实验间调整;90d 样本外 |
| 复盘记忆自我强化 | 结果数据定标签,正负例同时召回,时效衰减 |
| LLM 非确定性 → 回放不可复现 | 记录 N 次重跑一致率;报告决策分布而非单次 |
| API 限流/模型更新/数据延迟漂移 | 复现清单记录版本;模型更新 = 新实验线 |
| 公开信息无 alpha,私有数据质量不足 | 信源逐个前瞻检验(§2.1),淘汰制 |
| 三阶段增加叙事深度而非预测深度 | Critic 独立性 + 校准曲线 + playbook placebo 对照 |

## 8. 实施顺序(修订后)

1. **现在**:30d A 组(air + v0.8 门控)完成中——基线;
2. **下一步(唯一)**:实验 B 准备——情报栈信号逐个做前瞻性
   检验(§2.1),合格的信源压缩进 prompt,写预注册文档,
   跑 B(I1×G0)与 A 对照;
3. B 出结果后评审会:B 有增量 → 启动 C/D 与 playbook 因子;
   B 无增量 → 停止,回退"规则执行 + AI 研究层"。

playbook 库、三阶段、记忆检索的代码**在 B 通过门禁之前不写**。

## 9. 不变量(任何版本不得违反)

- PAPER/TESTNET/LIVE 凭证级隔离,LIVE 只能人工开启
- 沙箱边界由确定性代码物理执行,AI 无权修改
- 历史实验不可修改,新实验新 experiment_id
- Chain-of-Thought 不入库、不上 Dashboard
- 假设预注册先于实验,kill criteria 先于数据
- 没有 A/B 证据的能力不上线;没有前瞻检验的信源不进 prompt
