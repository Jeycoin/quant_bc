# 7d 回放对比报告:v0.5 → v0.6(横截面)→ v0.8(入场纪律)

> 窗口:2026-10-01 ~ 10-08(UTC),30m K 线,30min 决策周期,GLM-4.5-flash。
> 行情背景:**全市场下跌窗口**(buy&hold:BTC -7.5%,SUI -24.6%)。
> 模型训练 cutoff 未知,污染不可排除;所有结论需 30d/90d 样本外验证。

## 3. v0.6 归因分析(亏损从哪来)

### 3.1 regime 归因 —— 核心问题

| 入场 regime | 笔数 | 净盈亏 |
|---|---|---|
| TRENDING_BULL | 36 | **-18.73** |
| TRENDING_BEAR | 22 | **+6.55** |
| BREAKOUT | 3 | -0.89 |
| RANGING | 3 | +0.03 |
| 其他 | 3 | -1.81 |

**LLM 的 regime 分类有多头偏见**:下跌窗口中 36 次判"TRENDING_BULL"
(反弹被误判为趋势反转),全部亏损;判"TRENDING_BEAR"时(做空)反而
盈利 +6.55。分方向:LONG -20.61 / SHORT +5.73。

入场门(8h 动量 + EMA8/21 对齐)没能拦住这些多单:30m 尺度下,
熊市反弹的 8h 动量会短暂转正,EMA 快线也会短暂上穿——**门的时间
尺度与骗局的时间尺度相同**。

### 3.2 入场位置归因 —— v0.8 回调门的直接依据

| LONG 入场位置(range_8bar.pos)| 笔数 | 净盈亏 |
|---|---|---|
| ≥0.7(追高)| 22 | **-9.42** |
| 0.3-0.7 | 17 | -7.91 |
| <0.3(回调)| 2 | +0.97 |

与 Raschke/Connors《Street Smarts》的回调入场纪律一致:趋势方向
由高周期决定,但入场点必须在回调处,追高的期望为负。

### 3.3 波动收缩归因 —— v0.8 死市守卫的依据

入场时 vol_8bar/vol_48bar < 0.7(收缩):20 笔,-5.34——收缩期入场
没有动量,全部耗到 time-stop。

### 3.4 SUI churn —— v0.8 冷静期修复的依据

SUI 21 笔(占 31%)净 -13.25,其中 14 次 TIME_STOP。**TIME_STOP 原来
不触发冷静期**,导致"震荡→time-stop→立即重进→再 time-stop"循环。
TIME_STOP 本质是"论点没有动量",与 STOP_LOSS 同样应冷却。

### 3.5 出场结构

TIME_STOP 46/67(69%)——绝大多数仓位从未获得动量。这说明问题在
**入场质量**,不在出场管理(trailing/保本/止损结构本身工作正常)。

## 4. v0.8 改动(全部由 §3 证据驱动)

1. **回调入场门**:LONG 需 range_8bar.pos ≤ 0.6,SHORT 需 ≥ 0.4
   (配置 `entry_gate.long_max_pos / short_min_pos`,可关)
2. **死市守卫**:vol_8bar/vol_48bar < 0.7 禁方向单
   (`entry_gate.min_vol_ratio`)
3. **TIME_STOP 纳入冷静期**:与 STOP_LOSS 同等待遇(6h 同向禁入)

诚实声明:v0.8 参数在 v0.6 的同一窗口上调出,存在**样本内调参**
成分;真正验证需要 30d/90d 不同市场环境的样本外回放。

## 5. v0.8 结果(反事实回放,exp-99247a434073)

### 5.0 方法说明:为什么是"反事实回放"

v0.8 全量 LLM 回放(与 v0.6 完全同流程,后台运行中)单轮决策
受 GLM API 延迟制约约 2.5 分钟,336 轮约需 14 小时,且宿主机
夜间休眠进一步拉长。为按时交付,本次采用**反事实回放**
(`--counterfactual-exp`,新增于 `scripts/backtest_agent.py`):

> 逐字取 v0.6 实验记录的每一个 LLM 决策块(不重新调用 LLM),
> 送入**当前的**确定性门控(v0.8 入场门 + TIME_STOP 冷静期 +
> 既有的横截面/成本/风险门)重新执行整个窗口。

v0.8 的三项改动中有两项(入场门、冷静期)是确定性代码,反事实
回放精确隔离了它们的贡献;第三项(prompt 文档化)只影响 LLM
自身行为,不在本实验测量范围内,其效果由全量回放补充验证。
窗口、行情数据、组合参数与 v0.6 完全一致,两者可直接对比。

SUI 交易数从 19 降至 8。

### 5.3 门控拦截统计:新门确实在干活

| risk_status | v0.6 | v0.8 反事实 |
|---|---|---|
| PASSED | 1607 | 1432 |
| ENTRY_REJECTED | 135 | **307** |
| COOLDOWN | 4 | 7 |

新增的 172 次拦截中可辨识的触发原因(取自 rejection_reason):

- **追高门**:"chasing: LONG at range_8bar pos 0.707 > 0.6" 等,
  多头在区间高位被拦、空头在区间低位被拦;
- **死市守卫**:"dead market: vol_8bar/vol_48bar 0.55 < 0.7" 等,
  波动收缩期方向单被拦;
- 多数拦截是多个条件同时触发(如 RANGING 禁方向单 + 追高 + 死市)。

### 5.4 残留问题:TRENDING_BULL 误判仍未根治

| 入场 regime | v0.6 | v0.8 反事实 |
|---|---|---|
| TRENDING_BULL | 29 笔 -14.84 | 21 笔 **-15.43** |
| TRENDING_BEAR | 16 笔 +3.81 | 9 笔 +2.54 |
| LONG 合计 | 33 笔 -16.72 | 22 笔 -10.21 |
| SHORT 合计 | 18 笔 +2.99 | 9 笔 +2.54 |

入场位置门砍掉了 8 笔 TRENDING_BULL 入场,但留下的 21 笔总亏损
反而略增——**被拦掉的是小亏单,大亏单一笔没拦住**。这与 §3.1 的
诊断一致:问题的根子不是"在哪个位置进场",而是 LLM 在熊市反弹中
把 regime 误判为 TRENDING_BULL(多头偏见)。只要方向判断错,
位置门只能减少交易次数,救不了方向性亏损。这也解释了平均每笔
亏损变深(-1.21 → -1.48):小额噪音单被过滤后,剩下的是方向错误
的集中亏损。

### 5.5 结论

1. **v0.8 门控方向正确、幅度有限**:同样的 LLM 决策下,回撤
   -65%、交易数 -33%、净亏损 -71%(-13.73 → -7.64,按平仓口径),
   SUI churn 修复。门控是有效的"交易成本与噪音过滤器"。
2. **门控不是 Alpha 来源**:两个实验在 7.4 天下跌窗口中都小幅
   亏损(PF < 1),但均远胜全部被动基线(buy&hold -7.85~-25.89、
   固定网格 -7.78~-21.21、固定趋势 -0.73~-8.96)。系统当前的
   超额收益来自**防守**(少做、不做),不是进攻。
3. **下一个瓶颈是 regime 分类的多头偏见**(§3.1、§5.4),
   属于 LLM 判断层问题,不能用更多确定性门解决——需要 24h+
   长尺度动量对齐、或把 TRENDING_BULL 的入场证据门槛提高。
4. 反事实方法本身成为框架资产:以后每次改确定性门控,都可以
   在几分钟内对历史实验做同决策反事实对比,不必等 14h 全量回放。

## 6. 下一步建议

- **最高优先**:治理 TRENDING_BULL 误判——入场门增加 24h+
  动量对齐(ret_48bar 同向),或要求 TRENDING_BULL 入场提供
  更高置信度与多重证据;这是当前唯一的大额亏损来源
- 30d/90d 反事实回放(成本极低,优先于全量回放)验证门控
  参数不过拟合本窗口
- 横截面门拦截率偏低(14/135):观察离散度门实际触发频率,
  必要时调 min_dispersion
- BTC/XRP 在反事实中变差(小样本):30d 样本确认是否系统性
- LIVE 前必须:30d 样本外 + 长周期 testnet 实测
